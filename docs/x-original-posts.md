# X 原创推文和互动完成后发布

X 的 `post` 动作用于向当前账号发布原创文字或 PNG、JPEG 配图。支持既有 Edge、独立 Chrome/Chromium 和 Tabbit 自动连接。Browser Use 的只读观察连接保持人工模式。现有回复任务和账号的 `automatic_actions` 不变。

## 创建发布任务

在任务中心选择 X 账号，勾选“允许本任务向自有 X 账号发布原创推文”，选择在线队列，再保存原创正文、配图和时间。创建或编辑草稿不会开始发送，仍须通过明确启动操作进入持久队列。

API 与 MCP 使用同一任务策略：

```json
{
  "execution_channel": "cloud",
  "allow_owned_x_posts": true,
  "starts_at": "2026-10-20T00:00:00+08:00",
  "ends_at": "2026-10-27T00:00:00+08:00"
}
```

执行项设置 `action=post`、`target_owned=true`，`target` 必须等于账号中心返回的 `owned_target_url`。图片通过现有 `/api/media` 上传入口绑定本地文件与 SHA256，执行前重新核对哈希。正文采用保守的 twitter-text v3 加权预算；链接按 23 字符计，组合 emoji 可能被多计。最多四张 PNG/JPEG 配图。

原创发布仅在本任务明确启用时开放，并要求该连接已经允许自动回复。无需把账号的全局动作列表扩大到 `post`。本地执行器与线上控制端均在最终提交前检查冻结任务的启用选项和自有目标；线上不可用时保持等待。

## 完成互动后等待一小时

每个账号分别创建一个包含一条原创推文的发布任务，添加：

```json
{
  "outbound_after_task_ids": ["AP-前置互动任务ID"],
  "outbound_after_tasks_seconds": 3600
}
```

前置任务必须存在、包含该账号，并且真实/模拟模式一致。可等待同一账号的多个任务。必须逐项核验为 `confirmed`、有真实发布时间与发布引用；任务标记“已结束”不能代替这些证据。漏发、未知、失败、待执行或缺少发布时间时，发布任务保持等待状态，不冻结最终发送时间，也不生成发送尝试。

全部证据满足后，取最后一次实际发布时间加上等待秒数，写入执行项并固定清单。队列扫描会恢复已明确启动的等待任务，重启后从原数据库接续。各账号使用独立发布任务，互不等待。目标时间必须落在发布任务窗口内；如果在条件核验完成前已经错过目标时间，记录 `missed`，不自动追赶或补发。

此功能使用现有线上持久队列按时提交，未将排队状态当作平台已发布或平台原生定时回执。执行节点仍须保持可用；平台成功后的实际作者、全文、配图与时间全部核验后才标记 `confirmed`。

如果已有账号间隔或冷却截止晚于计算出的目标时间，任务显示需要重新排期，不会缩短现有等待或更改其他互动任务。

## 一次提交和回执

编辑框中已有草稿时停止，不覆盖用户内容。准备好正文和图片后重新核对身份，再检查最终队列授权并提交一次。成功响应先持久保存帖子引用，再独立打开帖子核验。回复或引用的回执不能冒充原创推文。

提交后断线或核验失败保留 `unknown` 和已有引用，仅进行只读核验，不重复发送。全局停止、账号冷却、任务窗口、任务哈希、队列租约和配额继续生效。

## 升级和验证

本功能同时涉及本机包与 Cloudflare 控制端。两端需使用此版本；旧线上控制端会安全地拒绝尚未开放的 `post` 动作。正常重载本机服务与 MCP 连接前应等待正在执行的项目结束，不中断提交中的互动。

离线测试位于 `test_x_original_posts.py`、`test_x_post_browser.py`、`test_tabbit_connection.py` 和控制端 `kernel.test.mjs`。浏览器测试拦截全部请求并使用合成页面，不访问真实账号。测试通过不代表这批五个账号已实际发出推文。

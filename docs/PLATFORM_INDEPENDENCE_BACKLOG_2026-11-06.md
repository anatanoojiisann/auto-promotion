# 平台独立处理：待集成事项

记录日期：2026-11-06。用户指出真实互动轮次不应固定依赖六个平台，并要求后续支持不同平台独立处理。本次先明确排除 Facebook。

## 问题

原整轮入口将 Telegram、Reddit、Instagram、Facebook、X、TikTok 固定为一组，导致单个平台的缺席或人工验证会阻碍用户指定的其他平台组合。一次性加入“不含 Facebook 的五平台”只是当前明确请求的兼容范围，不代表任意平台组合已经支持。

## 后续验收要求

1. 允许用户明确选择一个或多个受支持的平台；创建后冻结实际选择、账号和原任务。空选择、重复平台、未知平台和伪造账号绑定必须拒绝。
2. 各平台分别检查当前账号、目标、权限、配额、停止状态和独立回执。单个平台受阻时，其状态和原因独立保留，其他符合条件的平台继续。
3. 一台手机的前台操作仍须串行并保持同一设备控制权；可以并行的只读预检和回执查询不得越权或与账号锁冲突。
4. 超时、取消或结果未知的原执行只允许按原 ID 核查，不得通过更换平台、设备、任务或重启产生第二次提交；暂停不能擦除 unknown。
5. 完成率与时钟按用户实际选择的平台计算。每项必须有匹配账号、目标、正文与新平台 ID 的独立证据；从指令及必要准备到最后回执的完整时间单独计量。
6. 兼容已有六平台轮次和已冻结的五平台范围；升级及重启不能改变原任务、旧回执、授权和截止时间。覆盖并发启动、部分阻塞、人工接管、停止竞争、回执迟到和进程故障。

当前独立开发分支和模拟验证不等于已集成、上线或真实发布。涉及共享契约、账号权威队列和跨服务恢复的变更交由集成方按正式边界实施。

# 双通道执行

## 按任务选择通道

创建任务或按模板创建任务时，可以选择“在线队列”“本地队列”或“跟随默认”。API/MCP
使用 `policy.execution_channel`，取值为 `cloud`、`local`、`inherit`。未包含该字段的旧任务
继续使用原默认策略；迁移只添加通道表和提交保护，不改写旧任务政策、清单或哈希。

不同账号可以分别使用在线和本地通道。同一账号通过原持久队列串行执行，交接前检查
有效租约和待上传回执，先同步该账号的本地结果及全局额度账本，再确认云端账号归属。
云端按平台身份处理别名账号。已开始的正文、账号、目标、媒体、时间和尝试记录保持固定。
这版沿用单个绑定执行节点和同一本地任务库。

交接请求发出前，本机先持久保存 `handoff` 状态。响应丢失时保持等待，重启后读取云端同一
代次确认结果；不会恢复旧通道后重复发送。账号交接不会更改其他账号的通道。取消或过期任务
留下的未确认交接可由后续任务经过新代次核对接续，未知平台结果仍不重发。

明确选择在线的任务在连接、授权、额度或同步失败时等待，不自动改用本地。现有已授权的
独立本地范围可继续离线运行；已经交给云端的账号必须先确认本地归属，才能本地提交。
新工作区未接入云端时也可以使用本地任务。读取任务、创建草稿和模板不会交接或开始发送。

任务详情显示所选通道、各账号实际通道和等待原因。`GET /api/execution/pools` 增加
`account_channels`；任务详情增加 `channel`。云端新增签名控制接口 `/v1/account-channel`
及节点只读接口 `/v1/account-channel/status`。现有 `LOCAL_CHANNEL_UNTIL` 保留为旧账号的
默认保护，只有完成按账号交接的身份可以单独回线上。控制请求支持对原始 JSON 字节签名，
避免 Python/JavaScript 对 `1.0` 等数字的格式差异导致校验失败。

启用需要升级 Cloudflare 控制服务并正常重启本机服务，让迁移和新提交保护生效；不需要
解除现有全局停止或启动草稿。普通服务在首个已启动的显式通道任务入队后启用工作池。
云端尚未升级时，任务显示等待服务升级。全部测试使用隔离任务库和合成账号，不发布真实内容。

## 独立本地通道（当前配置）

本地通道不要求服务器初始化、签名检查结果或任何服务器请求。用户明确指定账号后，
本地数据库持久记录账号范围、数据库绑定、切换代次和有效期。原来的任务冻结、队列租约、
账号锁、停止开关、平台权限、去重、配额、节奏、投递窗口与回执检查保持生效。

`python -m auto_promotion.cli execution-channels --local-today --account <账号ID>`
可为多个 `--account` 指定范围，接管至北京时间当日结束。切换前必须没有执行中项目或
有效任务租约，不能清除其他待完成的交接。原服务器的未知或未结清回执项目不能本地重发。
今天线上领取和授权由 `LOCAL_CHANNEL_UNTIL` 暂停，避免两条通道并行。

这次已配置的独立本地权限也用于将来的额度降级：默认仍线上；明确的服务器写入额度错误
选择相同本地队列，无需检查服务器初始化。其他服务器错误保持原有等待规则。
期限结束后先排空本地租约、补传最终状态和额度，再返回线上。已提交或未知结果从不重发。
人工账号保持人工模式，不会被本地模式转为自动发布。所有切换和实际项目通道写入原审计日志。

已获明确授权的跨日续行可使用 `execution-channels --local-through-task <task_id>`，
重复提供任务 ID 和原有 `--account` 范围。截止时间取这些已启动任务的最晚结束时间，
不再被北京时间午夜截断；草稿、取消任务和范围外账号不能用于延长授权。该操作只延续
账号范围内原有本地队列权限，不启动草稿，不改变冻结清单、投递窗口、冷却或限额。
延长前必须排空租约，并将服务器的 `LOCAL_CHANNEL_UNTIL` 防并行期限同步至同一截止时间。

以下是未启用独立本地权限时可选的服务器检查模式；当前三个 X 账号不依赖该模式。

## 可选的服务器检查模式

默认使用 Cloudflare 授权、本机平台执行器。开启双通道后，只有明确的
`CloudWriteQuotaExceeded` 会触发原有本地执行通道。网络错误、认证失败、
平台限额、账号冷却和其他服务器错误继续停止执行，不触发降级。

两条通道共用原数据库、持久任务、清单、账号锁、执行池租约、配额账本和回执。
不删除 `cloud_control_required`，不回退 legacy 执行器，不调用绕过队列的后端。
只有未尝试的项目可以继续；未知结果、已提交、已排期及未结清云端回执不重发。
人工项目继续人工处理，逾期项目继续跳过。

## 配置

1. 在发送器数据库上运行 `python -m auto_promotion.cli execution-channels --binding`。
   输出的 `FALLBACK_NODE_ID` 和 `FALLBACK_STORE_ID` 是非秘密的部署绑定。
2. 把两个值加入 Cloudflare 的部署变量并部署新版 Worker。
3. 运行 `python -m auto_promotion.cli execution-channels --enable`。服务器确认绑定、
   停止状态、没有其他启用节点或有效云端租约、账本完整后，保存本地双通道策略。
   如果首次安装时额度已经连 SELECT 都阻断，只预置策略，等待额度重置后自动完成首次检查。
   没有可信检查结果时不会发放本地执行权限。
4. 在没有执行中写操作时正常重启发送服务，使调度器和消费者加载新版代码。
   启用双通道不启动草稿，不更改全局停止或真实发送开关。

本模式适用于一个工作空间、一台指定执行节点、一个持久数据库；平台执行池仍可并行。
服务器在两条通道中都拒绝其他节点领取/授权，以及注册其他节点。不要复制节点凭据和
数据库创建第二个发送器。解绑或迁移前，先停止领取，等租约结束、上传全部本地记录，
确认回到线上通道后再调整部署绑定。现有其他启用节点或身份别名会阻止本地接管。

## 自动切换和恢复

- 服务器只读 `/v1/standby-check` 在额度用尽时仍可工作：不建表、不迁移、不心跳写入、
  不领取云端租约，也不写云端授权记录；兼容 schema 1 和 2。
- 部分额度错误也阻断 SELECT。为覆盖此情况，正常线上同步后每分钟尝试保存服务器签名的
  备用检查结果（有效期截止下一个 UTC 零点前 5 秒）。只有服务器再次实际确认数据库额度
  耗尽，Worker 才能在数据库之外核验该签名、节点凭据、数据库绑定、账号权限和截止时间。
  缺少首次检查、签名不符、结果过期或其他服务器错误时保持停止。
- 本地接管前检查指定节点/数据库、服务端停止开关和账本覆盖。每个项目在领取后和
  提交前再次只读检查服务器停止状态、权限、账号限制、任务状态和云端是否已尝试。
  本地额度不得宽于服务器额度。检查失败时保持停止，不能把服务器完全断线当成额度耗尽。
- 接管状态和代次持久保存，重启后接续。接管截止取服务器重试时刻与下一个 UTC 零点前
  5 秒的较早值。额度恢复时先等本地租约结束，再补传回执、配额和最终状态，成功后切回线上。
  补传只传记录，不重复发送。恢复失败时继续等待，不放行线上消费者。
- 状态接口 `/api/execution/pools` 的 `channel` 显示策略、当前通道、切换原因和截止时间。
  审计事件 `execution.channels_enabled`、`execution.channel_changed`、
  `execution.job_channel` 保留启用、切换和实际项目通道。

双通道下，本地数据库是停止、暂停及额度变更的唯一来源；云端为其受约束镜像。
服务端 `/v1/settings` 和 `/v1/sync` 要求指定节点对本地数据库变更提供签名证明，
不能从另一份数据库直接更改云端控制状态。使用现有本地工作台执行停止或修改限额，
本地变更先持久保存再同步。服务器紧急吊销可移除或更改部署绑定、轮换操作员密钥；
旧签名立即失效。不得在本地仍有运行中操作时更改节点绑定。

测试使用隔离数据库和模拟平台，包括额度切换、非额度错误不切换、服务器只读检查、
停止/权限/租约、重启、账本缺失、未知结果不重发，以及恢复前先补传记录。

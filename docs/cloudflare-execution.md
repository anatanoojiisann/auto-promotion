# 持久化执行服务（Cloudflare）

云端使用 Workers + SQLite Durable Object，保存任务快照、冻结内容及哈希、账号路由、任务队列、租约、限额账本和结果。每个工作空间由一个 Durable Object 协调，同一事务内完成领取、账号互斥和限流检查。按当前每小时几十次的发送量，直接使用持久队列表，避免再维护一套消息队列状态。

执行节点保留平台凭据、Telegram 会话、浏览器登录和本地执行日志，通过 HTTPS 主动连接云端，不需要暴露本机端口。Cloudflare 不能直接运行现有 Edge、Tabbit 或 Python Telegram 会话。要在电脑关闭后继续发送，需要把相应执行节点迁到常开的服务器；浏览器节点仍需要可用的登录会话和桌面环境。

## 支持范围

| 平台 | 发送工作池 | 执行要求 |
| --- | --- | --- |
| Telegram | `telegram.mtproto` | 已连接的用户会话，入群与发送共用账号互斥 |
| X | `x.edge`、`x.tabbit`、`x.playwright`、`x.browser_use` | 接入方式独立；账号原有自动动作权限继续生效 |
| X 人工任务 | `x.manual` | 只生成人工处理记录 |
| Instagram | `instagram.graph`、`instagram.manual` | Graph 发布；第三方评论保留人工处理 |
| Discord | `discord.bot` | Bot 及目标频道权限 |
| TikTok | `tiktok.organic` | 已开放的 Organic API 能力及审核权限 |
| Reddit | `reddit.manual` | 保留人工社区互动 |
| 六个平台模拟账号 | `simulation.<platform>` | 仅合成测试结果 |

覆盖路由不等于开放新的平台权限。X browser-use 只读账号仍不能自动回复。新接入方式只需增加路由和执行适配器，不需要给每个账号创建一个线程。

发送池独立子进程运行，默认每池一个消费者；可通过 `ExecutionSettings.pool_workers` 调整。账号串行、共享桌面/浏览器互斥、平台并发和全局并发仍会进一步约束。核验、统计、报表、收件箱和内容采集各自运行，避免一个慢调用阻塞全部后台工作。

## 一次发送的过程

1. 用户明确启动任务，原有流程冻结账号、策略、内容、目标、媒体和时间。
2. 调度器把引用写入本地持久队列，并把业务快照与最近限额账本同步到云端。普通同步不会解除停止或开启真实发送。
3. 节点按绑定的平台池领取指定任务，云端以租约占用账号身份和共享浏览器资源。
4. 原有 Engine 再次检查资格、健康、冻结清单、顺序、限额和时间窗，持久化唯一尝试编号。进入平台适配器前及平台提交前再次校验云端授权。
5. 先保存本地平台回执，再上传云端。上传失败写入持久化补传表，恢复后只补传回执。
6. 节点失联或租约过期，云端任务进入结果不明，不能重新领取。只读核验可将其更新为已确认，仍不产生新的发送尝试。

Cloudflare 上保存的是持久业务快照与执行账本，本地工作台仍是任务编辑入口，本地数据库仍是执行节点日志。首版不是多个节点同时编辑同一份任务；备用节点接管前需要恢复匹配的业务日志与凭据，并注册相同账号身份，不能用一份空数据库自动接管未知结果。

## 部署

部署和启用分开进行。先通过测试及构建，再执行：

```powershell
cd cloudflare/control-plane
npm ci
npm test
npm run check
cd ../..
./scripts/deploy-cloudflare-control.ps1 -Login
```

Cloudflare 登录授权须由账号持有人完成。部署脚本生成并私下保存 `var/cloud-control-operator.key`，通过标准输入写入 Worker Secret；不会输出密钥。新云端默认停止且不允许真实发送。

随后在确认无执行中的发送/入群、已备份数据库后，将现有节点绑定到部署输出的 HTTPS 地址：

```powershell
.venv/Scripts/python.exe -m auto_promotion.cli cloud-bootstrap `
  --url https://<deployed-worker>.workers.dev `
  --node-id windows-primary `
  --operator-token-file var/cloud-control-operator.key `
  --adopt-local-policy
```

`--adopt-local-policy` 明确复制本地当前停止开关、真实发送开关及限额，不提高额度、不启动草稿、不修改冻结内容。去掉该选项则仅同步和绑定，云端保持停止。可重复提供 `--account` 将节点限定到指定账号；默认绑定当前账号和实际用到的工作池。新账号或接入方式需要重新绑定节点范围。

节点凭据保存为私有 `var/cloud-node.env`，下一次服务启动时自动读取。备份此文件与账号会话，限制其操作系统访问权限；不要上传到 Git、聊天或云端业务快照。工作台 API 继续监听本机。

```powershell
.venv/Scripts/python.exe -m auto_promotion.cli cloud-status
.venv/Scripts/python.exe -m auto_promotion.cli pools-status
.venv/Scripts/python.exe -m auto_promotion.cli cloud-sync
```

已有 Windows 任务计划程序继续守护服务，启动后使用分池模式。Linux 节点可以用 systemd/容器守护相同 CLI；禁止把两个未同步的本地任务库注册成同一账号的可重试发送源。仅重启服务不会开启新任务。

## 运维与验证

- `GET /api/execution/pools` 展示各池队列、心跳、云端同步状态及待补传回执数。父调度器存活不代表每个池都正常，需同时检查这些数据。
- 本地队列使用索引查找到期任务；云端领取事务按账号身份和节点资源排除占用。全局与平台并发上限对所有池生效。
- 云端账号停止/冷却取更严格值，普通快照不能清除它们。解除云端停止、禁用或冷却需要维护人员明确操作云端控制接口；不能依靠旧快照覆盖。
- 暂停、撤销和更严格的本地约束仍在原平台提交前检查。工作台中明确修改停止开关或调度额度时，变更会持久化后同步到云端；同步失败保留待同步标记，发送节点约十秒一轮重试。普通任务快照不能解除停止。网络分区时本地停止无法立即通知其他节点，紧急停止多个节点时可直接通过云端 operator `PUT /v1/settings` 设置 `global_stop: true`。
- 云端启用后，本地持久标记要求云端授权。丢失环境变量或云端不可用时不会降级为本地直接发送。
- 数据库本身校验发送尝试所属的有效工作池租约。升级前已加载的旧 MCP 连接不能直接消费发送尝试；需要刷新连接以读取新状态字段。已明确启动的任务仍由后台队列接续，不通过旧连接直接发送。
- 回执不明、平台原生排期、管理员审批分别保留状态；本地取消不会撤回平台已接受的排期。
- 初期每个工作空间一个协调对象；工作空间之间天然隔离。扩容先增加不同平台的执行节点和消费者，仍受账号、平台及全局限额限制。真正达到单协调对象瓶颈后再按工作空间分片，不能按账号分片后丢失全局限额。

自动测试覆盖并发领取、账号与浏览器互斥、停止开关、统一限额、租约过期、平台权限、任务冻结、回执补传、重启恢复、只读核验和“不明不重发”。Cloudflare 本地模拟器的 HTTP 验收使用模拟账号，不向真实社交平台发送。

## Schema 2：写入预算和维护时钟

双通道（默认线上，写入额度耗尽后接续本地队列）的部署绑定、切换边界和恢复流程见
[双通道执行](execution-channels.md)。未配置双通道时继续按原有规则停止等待。

普通成功任务的云端 SQLite 核心流程实测为 **6 行写入**：入队 2、领取 1、发送前授权 2、回执 1。
任务行使用 `WITHOUT ROWID`，仅保留待发送时间和尝试时间两个索引。`claimed_at`、`attempt_at`、
`completed_at`、`quota_scopes`、账号与任务的 `pacing_until` 与原有租约、尝试编号、结果同一行保存。
配额查询合并历史账本与任务内的尝试记录，按尝试编号和维度去重；未知结果仍计配额。
所有账号别名共用身份限额与节奏，任务级节奏继续跨账号生效。领取与发送前授权保持独立事务。

6 行不包括共享账号/任务定义和同步游标、首次迁移、心跳/闹钟、必要续租、限流冷却、
失败及后续核验。500 条合成任务的本地 workerd 基准为 3,000 行写入；读取量也纳入基准，
避免单纯用大量扫描换取写入下降。更大的历史库应重新测量读预算。
重复授权、重复已确认或原生排期回执、已记录维度的配额回传不产生重复业务写入。
显式启动与操作员审计继续保留在原日志中；单条执行的证据改由持久任务行提供。

- 节点诊断心跳最多每 300 秒持久化一次。客户端有即将到期/执行中任务时最多每 60 秒探测，
  空闲时每 300 秒；近期成功的其他请求可以代替探测。心跳不授予发送权限，最终授权仍访问云端。
  本地停止同步、队列扫描和回执补传不会等待这五分钟。
- 本地执行器继续按原来的到期扫描启动任务。云端闹钟只负责最近的租约到期或发送窗口截止，
  不再每分钟重设。新任务/领取可以把闹钟提前；续租不会频繁后移已有闹钟，已有较早闹钟允许
  多一次只读唤醒后再设到新到期时间。无工作不重新设闹钟。
- 云端租约仍为 180 秒，剩余 60 秒才续租；正常每 120 秒一次。客户端以服务端返回的相对
  时长和单调时钟计算，网络耗时扣在安全余量内。旧客户端提前续租仍成功但云端不写库。
  本地 10 秒的存活检查继续保留；续租失败不延长本地认定的云端有效期，也不允许续活过期租约。

首次打开旧工作空间时，在一个 SQLite 事务中迁移：原任务保留为只读 `jobs_v1_archive`，
历史配额改名为 `quota_history`，`quota_events` 成为合并查询视图。原冻结内容、租约令牌、
尝试编号、停止开关、冷却、节奏、未知结果和原生排期均保留。配额不足或其他迁移异常会回滚，
保持停止执行；下一次可重新迁移。迁移有一次性写入开销，不能在当日写入额度已耗尽时完成。
不可用旧代码直接回滚此 schema，也不能用迁移归档覆盖迁移后的尝试记录。

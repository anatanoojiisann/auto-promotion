# 业务增长与回复处理

新增“业务增长”“回复待办”入口，共享内容池增加“核对资格与文案”和“定时采集来源”。所有数据保存在原工作台数据库，启动时增量建表，原账号、任务、审批和外发清单保留。

## 完整流程

1. 账号中心登录并检查真实账号，建立号池，填写真实角色、语言、主题和产品事实。
2. 只读采集或导入公开相关内容。核对原问题、语言、置信度、有效期、目标规则、许可及证据；允许互动时必须填写真实许可证据。
3. 业务增长中设置观察周期、目标地区、下载目标、付费目标、每日互动目标及成本边界。留空的指标表示未设置，不自动赋予数值。每日互动目标不会调高发送额度。
4. 创建推广活动，关联业务目标；用不同渠道标记区分账号或活动。
5. 创建执行批次，通过原有直接启动后执行。新功能不解除停止、不启动发送、不更换已启动账号或正文。
6. 导入商店渠道指标及应用事件，比较目标进度，处理回复待办。新增回复任务准备完整内容后明确启动。

## 渠道链接

填写不带查询参数的官方 App Store 应用链接。渠道的提供商令牌 `pt` 必须来自 App Store Connect；不填写时只保存待配置渠道，不生成可归因链接。渠道标记采用最多30位英文、数字、下划线和连字符。记录不可原地换标记，以避免历史数据与已使用链接混淆；需要新参数时创建新渠道。

同一个应用、数据范围、提供商令牌和渠道标记只能登记一次。真实业务目标不能关联模拟账号或模拟活动，真实／模拟目标分开保存。

本模块根据已提供的令牌组装链接，不核验令牌归属、不连接 Apple 登录，不从链接推断逐用户安装来源。官方说明：[Apple 渠道链接](https://developer.apple.com/help/app-store-connect-analytics/acquisition/campaign-links/)。小样本数据可能不显示，应保留未知，不能填零。

## 应用事件

支持 JSON / CSV 文件及受原工作台认证保护的接口。批量导入最多5000条。需要提供匿名、稳定、跨导出一致的 `subject_key`，入库时再次散列，不保存原始用户标识。不要使用手机号、邮箱、登录凭据或支付卡信息。

```json
{
  "items": [
    {
      "source": "application-backend-export",
      "event_id": "export-event-unique-001",
      "kind": "first_download",
      "subject_key": "anonymous-stable-user-key",
      "channel_id": "填写本工作台的实际渠道ID；未知来源时留空",
      "occurred_at": "2026-10-14T09:00:00+08:00",
      "country": "US",
      "evidence_reference": "backend-export-20261014-row-1"
    }
  ]
}
```

`kind` 可选 `first_download`、`first_generation`、`trial_start`、`first_charge`、`refund`。试用必须包含实际 `trial_ends_at`；扣费和退款必须包含 `transaction_id`、`amount_minor`、`currency`，金额以该币种的最小单位记录，例如 USD 的美分、JPY 的日元。退款引用原扣费交易，币种一致、时间不早于扣费，累计退款不超过原扣费。

事件按目标、来源、事件编号去重；同编号数据变化、同用户重复首次事件、交易跨来源重复均拒绝，整批回滚。非交易事件不能携带金额，未来发生时间拒绝。证据字段表示导入者提供的来源依据，不代表系统独立核验银行扣费或 Apple 收据。

## 商店指标和成本

```json
{
  "items": [
    {
      "channel_id": "填写实际渠道ID",
      "day": "2026-10-14",
      "country": "US",
      "source": "App Store Connect export",
      "evidence_reference": "export-20261014-row-12",
      "first_downloads": 12,
      "product_page_views": null,
      "spend_minor": 0,
      "currency": "USD"
    }
  ]
}
```

同一渠道、日期、地区重新导入会修订原记录，不累加。每行至少提供一项实际指标；`null` 或缺省表示未知。CSV 数字字段可填数字，未知字段留空或填写 `null`。日期按业务目标时区解释；目标指定地区时，无地区数据不计入该地区结果。商店指标按完整自然日录入，观察周期建议从午夜开始。

商店汇总下载和匿名用户事件分别展示，不能相加。匿名事件漏斗按观察期内首次下载入组，后续试用成熟、首笔扣费和退款可在观察期结束后补充。首次下载前的事件不计入漏斗；无匹配下载事件的数据明确显示。只有实际试用结束时间已经到达的用户进入到期转付费分母，未到期用户单列。到期前提前购买不当作试用到期后扣费。收入和成本分别按币种统计，不隐含换汇。

所有比例标记为已观察数据，覆盖未确认完整；缺少商店指标、有效分母或成本数据时保持未知。现阶段提供本机导入和认证接口，**不会自动登录 App Store Connect、拉取商店报告或连接应用生产数据库**。接入真实数据时，可由现有应用分析服务导出约定格式，在本机导入；业务账号和生产接入凭据仍需配置。

## 回复待办

自动同步已保存的真实反馈事件，重启和重复同步不生成重复待办。可以记录待处理、审核中和结束讨论。

“创建后续任务”只创建草稿，固定原账号、原目标白名单，不入新群。回复编号和目标自动带入外发编辑器，完整正文由人审核；通过客户端开始发送或 Codex 明确执行指令启动。相同待办重复创建会返回未结束的后续任务。只有后续任务包含针对该回复的已核验投递，才可标记“已回复并核验”。已排期和未知结果不能作为已回复。

原回复正文不保存，处理前需要在平台核对消息。目前自动回复采集仍仅支持 Telegram，其他平台不会被报告成零回复。页面每30秒更新待处理数量，通知在工作台内展示，不对外发消息。

## 内容来源与持续运行

来源默认停用；启用后，原只读报告调度每轮检查到期来源，最小15分钟间隔，只读取指定公开 Telegram 群，不入群或回复。账号冷却和独占执行权仍生效；来源使用数据库租约防止多个调度器同时读取。

刷新保留人工核对的许可、有效期、主题、受众和草稿。原消息正文变化时清空旧回复草稿，要求重新核对。更新共享内容不改动已生成执行批次的快照。采集失败显示“读取未完成”，等待下一周期，错误响应和凭据不会写入结果。

电脑和工作台需持续运行。业务增长页展示后台发送、只读调度、全局停止、角色缺失和未结束任务的阻碍；这些配置状态不等同于平台在线保证。可用 `serve --reports-only` 只运行工作台、报告与只读采集；普通 `serve` 调度已明确启动的任务。

## 接口

所有接口沿用工作台的 Bearer 或本机会话认证及跨站检查。

| 接口 | 功能 |
| --- | --- |
| `GET /api/growth/readiness` | 账号、角色、内容、运行准备情况 |
| `GET/POST /api/growth/goals` | 列表／设置业务目标 |
| `GET/PUT /api/growth/goals/{id}` | 业务报告／更新目标 |
| `POST /api/growth/goals/{id}/channels` | 登记渠道 |
| `POST /api/growth/goals/{id}/events` | 原子导入应用事件 |
| `POST /api/growth/goals/{id}/store-metrics` | 导入商店指标及成本 |
| `GET /api/growth/inbox` | 分页回复待办 |
| `PATCH /api/growth/inbox/{id}` | 更新处理记录 |
| `POST /api/growth/inbox/{id}/followup` | 创建新任务草稿 |
| `GET/POST /api/growth/feeds` | 列表／登记只读采集来源 |
| `PUT /api/growth/feeds/{id}` | 更新启用状态和读取范围 |
| `POST /api/growth/feeds/poll` | 读取已启用的到期来源 |
| `PUT /api/opportunities/{id}` | 按版本核对资格和文案 |

MCP 增加 `list_business_goals`、`business_growth_report`、`save_business_goal`、`import_conversion_events`、`import_store_metrics`、`list_reply_inbox`。这些工具不授予平台互动权限。

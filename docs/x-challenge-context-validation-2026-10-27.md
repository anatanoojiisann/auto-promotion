# X 验证页观察与持久阻断：本地修复验证

## 基线与范围

基于公开 main `f267858d18c3ba13375f8dfe274b453b17cf9363` 的独立 detached 工作区实施。
本轮没有提交、上传、远端 CI、部署、真实账号操作或验证码交互。原本地分支和未跟踪诊断文档保持原样。
现场截图与自动检查没有可靠的 context/tab 绑定，缺少实际加载代码指纹；这些修复针对已复现的代码条件，不能据此声称重建了全部现场因果或已经部署生效。

## 行为变更

- `backends/browser.py::_run` 在导航主页前检查账号状态，避免覆盖现有挑战页证据。
- `check_x_context_state` 仅观察当前账号已打开的同一 context，不扫描其他浏览器或其他账号。起止两次确认所选页归属和存活；导航、加入新页、读取失败或页数超限均使观察不可用，不假报健康。关闭的旁页可以忽略；旁页读取失败时仍继续寻找可靠挑战证据。
- 检查最多 32 页，每类状态组件最多 32 个；超限不会把观察缺失当作无挑战。沿用浏览器现有 RPC 超时，不产生额外平台导航或验证码请求。
- 仅可信平台 URL 和实际可见组件可触发挑战；正文里出现 captcha 不触发。组件自身及祖先的 `opacity:0`、隐藏、`aria-hidden` 状态均排除。
- `legacy_x_state_error` 只映射可信 `BackendError.safe_code` 的精确旧代码：`BrowserVerificationRequired`、`BrowserAccountRestricted`、`BrowserLoginRequired`，进入既有结构化账号阻断链。不会根据任意异常消息或页面正文匹配验证码。
- 执行前、无回执且明确未提交的结果为 `failed_known`；已经提交或持有 ID 的结果保持 `unknown`。检测器仅触发安全停机与人工处理，不执行或绕过挑战。
- `account_blocks.observe` 对每个独立新证据推进 generation，包含首次恢复探测仍在途、还没有 `health_checked_at` 的情况。重复事件仍去重；普通 healthy、重启和迟到成功不会自动解除新阻断。恢复仍需新鲜、同身份检查和显式操作。
- 未增加页面正文、URL、cookie、token 或浏览器目录的诊断持久化字段；复用原有脱敏分类、事件代次和运行指纹字段。

- 隐藏组件：1 方法，透明和 aria-hidden 两个子场景失败。

- Ruff、Python 格式检查、Prettier 通过；sdist 和 wheel 构建成功。本项目没有独立配置的 typecheck，未声称运行了额外类型检查器。

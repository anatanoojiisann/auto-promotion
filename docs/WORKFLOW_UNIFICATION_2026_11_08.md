# Local workflow unification

The existing AP task, item, manifest, attempt, authorization and platform receipt remain authoritative. Temporal only admits explicitly registered new frozen local phone tasks after an explicit MCP start. It never sends through an activity or imports historical tasks. A database trigger also fences older execution clients until admission. Missing platform receipt remains unknown across timeouts, stop and recovery.

The authenticated account control endpoint reads stops and selected connection evidence directly. It does not scan all queues, grant sending authority, or replace a desktop login with a phone observation. Native actions remain serialized on one phone; waiting business workflows have no physical lease.

Only privately commissioned Telegram adapters and exact new task IDs use the single native pass. One independent baseline replaces the previous prepare/type/discard/reopen sequence. Fresh native identity, target, content, control, single-use authorization, final dispatch and stop checks remain in the normal sender. Default and historical routes remain unchanged.

A new receipt-detached result releases only physical ownership after one final dispatch and a correlated, fresh, trusted quiescent native observation. The business result stays unknown until the independent Telegram reader verifies a native ID and external reference. Legacy unknowns, unfinished gestures, absent grants, stale screenshots and mismatched account/target/body/adapter never release this fence.

An exact content-identical replacement may exempt one old known-unsent attempt only with a separate audit entry and proof of settled original attempt/job, no submit authorization, no outbox and settled preparation. All old results, usage and limits remain. An unknown can never use this path.

AP and control/fleet keep separate original stores, credentials and environments. The local Temporal Server uses its own PostgreSQL store and loopback endpoint; no Cloudflare is required. The earlier read-only pilot history is retained separately. Configuration, databases and screenshots must remain ignored and protected.

The AP integration also preserves the source modifications already loaded by the existing sender through a three-way merge against its base. This includes its existing account controls, task channels, text integrity, interaction intent and UI changes. No source in the older running checkout was reset or overwritten.

Validation includes protocol proof rejection, real fleet-state ownership release with simulated observations, one native tap with detached receipt, account control and selected connection boundaries, original-queue admission fencing, and official Temporal worker recovery without another admission. Hardware and real promotion acceptance must be reported separately with native receipt evidence and measured timings. A passed synthetic test is not a successful publication.

# 定期采集互动效果

工作台「互动统计」新增观看、点赞、回复的逐条累计值、上次采集变化和历史快照。
每条已核验发布的真实互动每三小时到期读取；账号间隔至少一分钟，一轮每账号最多
读取一条、共五条。发送前两分钟、浏览器占用、账号禁用／冷却／风控时延后。
读取失败账号至少休息十五分钟。平台限流仍进入已有账号读取冷却。

Windows 上，必须使用有界面浏览器的 X 账号会在独立的后台桌面采集，避免抢占
当前窗口；Tabbit 的采集命令也会隐藏终端。账号连接和人工登录窗口不受影响。
如果系统暂时无法创建后台桌面，采集会沿用原来的窗口方式，避免停掉统计。

首轮依次补齐已有记录，数量多时需要时间。电脑和服务运行时持续采集，重启后按
持久状态恢复。离线后只能读取当前数量，不补造离线时的历史快照。

## 当前覆盖

- X：既有官方 API、Tabbit 和隔离浏览器连接。只读取本账号已发布内容的
  `external_reference`，同时核对已登录账号、实际帖子 ID 和作者；回复指标属于
  我们发出的那条回复，不取原帖或相邻回复的数量。API 读取 public_metrics；
  页面读取无歧义的对应控件。未提供的指标为 null。
  Tabbit 采集先使用完整侧栏布局并等待账号用户名显示，再同时核对账号菜单和
  Profile 链接。紧凑侧栏没有用户名不能据此判为账号切换，也不能跳过身份检查。
- Telegram：在原读取预算和账号身份校验下，按原生消息 ID、会话 ID、内容和
  自己发送标志核验消息，读取消息自带的观看、点赞、回复、转发和表情数。
  点赞只合计 👍／❤，其他表情计入 reactions；缺少字段不猜零。多消息媒体组
  暂不合计，避免虚增观看。群消息没有观看字段时保留未知。
- Facebook／Instagram／TikTok 公开互动及 Reddit、Discord：本轮未接入定时
  指标提供者，显示「暂不可获取」。TikTok 私信显示「不适用」。

X 的 views 为帖子浏览次数，不是视频播放次数或去重人数。平台回复累计计数与
既有「他人直接回复」事件统计分别保存，不把计数冒充完整回复列表或回复率。
页面的 K／M／万等缩写标为约数，不计算精确增量；真实下降也会保留。
失败快照不覆盖历史成功快照，当前缺失显示不可获取，历史按钮仍可查看之前的值。

采集只使用 engagement 只读操作，不创建发送尝试、不改变原任务或回执，也不会
解除停止或修改额度。`--reports-only` 服务也会运行这个采集器，保持外发关闭。

## 接口

- `GET /api/engagement?limit=50&offset=0`：全部日期已核验互动的最新值、覆盖和分页。
- `GET /api/items/{item_id}/engagement?limit=100`：最近快照，含时间、来源、缺失与约数标记。
- MCP：`engagement_statistics` 和 `engagement_history` 仅读取已保存记录。
- `auto-promotion collect-engagement`：执行一轮到期只读采集。

本机库新增 engagement_snapshots、engagement_polls；不修改旧条目或冻结清单。
参考：[X 指标](https://docs.x.com/x-api/fundamentals/metrics)、
[Telegram 消息字段](https://core.telegram.org/constructor/message)。
